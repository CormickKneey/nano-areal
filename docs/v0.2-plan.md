# nano-areal v0.2 更新计划（定稿：Qwen3.5-2B 学生 + Qwen3.8-27B 蒸馏教师 + dsh）

> 基线：nano-areal v0.1（Qwen3-0.6B + BFCL-V4 + GRPO，~3.5k 行）
> 上游：areal-project/AReaL main @ 2026-09-16（v2.1.0 之后）
> 智能体：deepseek-ai/deepseek-harness（dsh 0.1.6-alpha）
> 硬件：2×RTX 4090 24GB（async 主模式）+ macOS Apple Silicon（`--sync` 调试）

---

## 0. 一句话目标

**用 dsh 作为不可修改的外部智能体，通过 nano-areal 的 DeepSeek/OpenAI 兼容代理捕获其多轮工具调用轨迹；在 2×4090 上对 Qwen3.5-2B（原生 VLM）做异步 GRPO，并以 Qwen3.8-27B 为教师做 token 级 on-policy 蒸馏。** 对应 AReaL 2.0 的 `agent_service`（#1383）+ `mopd`（#1592），保持 nano 体量。

## 1. 模型

### 1.1 学生：`Qwen/Qwen3.5-2B`（已核对）

| 项 | 值 |
|----|----|
| 类型 | Causal LM + Vision Encoder（原生 VLM，图/视频） |
| 结构 | 24 层 = 6 × (3 × (Gated DeltaNet → FFN) → 1 × (Gated Attention → FFN))，hidden 2048，FFN 6144 |
| Gated Attention | 8 Q / 2 KV heads，head_dim 256，partial RoPE |
| Gated DeltaNet | 16 V heads，head_dim 128，conv kernel 4 |
| 词表 | 248,320（与 27B 教师相同 tokenizer，embedding 与 lm_head 绑定） |
| 上下文 | 262k 原生 |
| VLM 指标 | 与 Qwen3-VL-2B 同级或更好（MMMU 64 vs 61，CharXiv 59 vs 37，OCRBench 84 vs 79） |
| 推理支持 | vLLM（需带 GDN kernel 的版本）；**vllm-metal 官方支持 Qwen3.5/3.6/3.8 hybrid（含 mlx_vlm M-RoPE）** |

### 1.2 教师：`Qwen/Qwen3.8-27B`（已核对）

- `Qwen3_5ForConditionalGeneration`，64 层同款 3:1 hybrid，vocab 248,320，原生 VLM，MTP。
- 与学生同 tokenizer → 可直接用 AReaL mopd 方式做 token 级蒸馏（教师 `prompt_logprobs=1` 对学生采样的 token 序列打分，参考 `areal/engine/vllm_remote.py::compute_logp`）。
- 4090 上用 AWQ/GPTQ-Int4（≈16–18 GB）；Mac 上可用 `mlx-community/Qwen3.8-27B-8bit`（vllm-metal 官方示例 checkpoint）或你提的 HauhauCS GGUF（llama.cpp，仅生成、无 prompt_logprobs）。
- HauhauCS 的 GGUF 是社区 uncensored 量化，**不能训练**，作为教师亦建议换官方权重以保证打分分布可信。

### 1.3 为什么不是别的组合

| 组合 | 结论 |
|------|------|
| Qwen3-VL-2B 学生 + 27B 教师 | tokenizer 不同（152k vs 248k），token 级蒸馏不可行 |
| 27B QLoRA 直训 | 放弃 nano-archon、吞吐极低、macOS 不可行 |
| 27B GGUF 直用 | 推理格式，无 BF16 权重 |

## 2. nano-archon Qwen3.5（学生实现，本版最大改动）

```
nano_areal/archon/
├── model.py            hybrid decoder：按 full_attention_interval=4 交替 GDN / GatedAttention 层
├── gdn.py              [新] GatedDeltaNet：q/k/v/z/a/b 投影、causal conv1d(k=4)、
│                          chunk_gated_delta_rule、FusedRMSNormGated、输出门
├── attention.py        GatedAttention：Q/K/V + 输出门 sigmoid，partial RoPE(rotary 64/256)
├── vision.py           [新] ViT + patch merger + DeepStack（复用 Qwen3-VL 设计）
├── mrope.py            [新] M-RoPE（时间/高/宽三维位置）
├── state_dict.py       HF `Qwen3_5ForConditionalGeneration` ↔ archon 名称映射（含 MTP 头丢弃）
├── lora.py             [新] LoRA on q/k/v/o/gate/up/down；ViT 冻结
└── losses.py           [新] GRPO / CISPO / GSPO / Dr.GRPO + 蒸馏项
```

**GDN kernel 策略**

| 平台 | 实现 | 备注 |
|------|------|------|
| 4090 | `fla.ops.gated_delta_rule.chunk_gated_delta_rule` + `causal_conv1d`（可选依赖 `gpu` extra） | 与 AReaL `archon/qwen3_5/model/model.py` 一致 |
| macOS / 无 fla | 纯 PyTorch chunked 实现（移植 HF `modeling_qwen3_5.torch_chunk_gated_delta_rule`，~120 行） | 速度慢 3–5×，只用于 `--sync` smoke；同时作为 4090 上 kernel 正确性的对拍参考 |

对拍验收：`scripts/test_archon_parity.py` 对 HF `Qwen3_5ForConditionalGeneration` 在文本 + 单图输入下 logits 误差 < 1e-3（bf16 下按 atol 2e-2 放宽）。

> AReaL 的 `archon/qwen3_5` 只有文本、硬依赖 fla，且 MoE/Ulysses 等 nano 用不到，只参考层结构与 state_dict 命名。

## 3. 蒸馏（对应 AReaL mopd）

**loss** = `rl_coef · L_GRPO + distill_coef · Σ_t mask_t · (logp_student,t − logp_teacher,t)`（学生采样 token 上的 reverse-KL 单样本估计，与 AReaL `loss: {rl_coefficient, distillation_coefficient}` 同构；默认 1.0 / 0.5，可配 `rl_coef=0` 做纯蒸馏）。

**教师放置（2×4090）**：GPU0 = 学生 vLLM（2B 权重 ~5 GB + KV），GPU1 = trainer。27B-Int4 无法与二者常驻共存，采用 **分时教师阶段**（≈ AReaL `scheduling_strategy: colocation, fork`）：

1. rollout K 步（默认 K=4），轨迹入 buffer；
2. 学生 vLLM `sleep(level=2)` 释放显存 → GPU0 起教师 vLLM（Int4，`max_model_len=16384`，`enable_prefix_caching`）→ 批量 `/v1/completions` `prompt_logprobs=1, max_tokens=1` 打分 → 卸载；
3. 学生 `wake_up` + 权重同步。教师阶段每次约 40–90 s（27B Int4 prefill 16k × 32 条），吞吐损失 30–40%。
4. 备选：教师跑在 Mac（vllm-metal + `mlx-community/Qwen3.8-27B-8bit`）经 LAN 打分，GPU0 无需分时；`prompt_logprobs` 在 vllm-metal 上是否可用需 S1 验证。

**教师图像输入**：VLM 任务的轨迹含图，教师打分时需同样的图 → 教师请求带同一 `image_url`，processor 相同（同族），image token 数一致，直接对齐位置。

**触发策略**：教师只对 pass 率 < 阈值（默认 0.5）的任务组打分，其余组纯 GRPO，节省教师时间。

## 4. 锚定智能体：dsh（DeepSeek Harness）

### 4.1 契合点（来自 dsh 源码/README，已核对）

| dsh 能力 | 对 nano-areal 的意义 |
|---------|-------------------|
| Python SDK `DeepSeekHarness(dsh_home, cwd, provider="deepseek-official", model=..., base_url=..., api_key=...)`，子进程 + stdio JSON-RPC | `DshAgent.run()` 用 SDK 起 dsh，`base_url` 指向代理、`api_key` 用代理签发的 session key（= AReaL `rollout.agent.mode=subproc`） |
| `llm-deepseek` 适配器支持 `protocol: chat-completions` + 自定义 `baseURL`（`--patch` yml 切换） | 代理需实现 **DeepSeek 风格 Chat Completions**：SSE 流式、`reasoning_content`、tool_calls，忽略 `dsh_session_log` / `dsh_plugin_packages` 扩展字段 |
| `sdk-minimal` profile：仅一个持久 shell 工具，`DSH_SYSTEM_PROMPT` / `DSH_CONTEXT_WINDOW` 可配 | 系统提示最短 → 2B 模型可承受；`model` 由 SDK 初始化请求指定 |
| `RunResult(final_response, finish_reason, events)`；`session_id` 可复用 | 奖励在 agent 侧算好后 `POST /rl/set_reward`；`finish_reason=max-tokens/error` 判 0 |
| 图像：附件投影为 image_url/base64；`browser-use` / `computer-use` 产生截图 | VLM 入口：任务附图或 dsh 自截图，代理用 HF processor 处理 → 复用多模态轨迹能力 |
| 每个模型请求写入 session log | 校验代理捕获的 token 序列完整性 |

## 6. 上下文长度（max_model_len）

Qwen3.5-2B 只有 6 层 full attention（2 KV heads × 256），**KV ≈ 6 × 2 × 2 × 256 × 2 B = 12 KB/token**，比 Qwen3-VL-2B（~114 KB/token）小一个数量级；GDN 层为固定大小递归状态。因此 KV 不再是瓶颈，瓶颈变为训练侧激活。

| 轨道 | 建议 `max_model_len` | 依据 |
|------|---------------------|------|
| L0/L1 单轮 | **4096** | 图 token ≤ ~650，prompt+answer < 2k |
| L2/L3 dsh | **32768** | dsh sdk-minimal 系统提示 + 工具 schema 估 2–4k，每轮 shell 输出截断 2k，5–10 轮 → 10–20k；32 并发 × 32k KV 仅 ~12 GB；教师 Int4 27B 同样 32k 可入 24 GB（16 层 full attn × 4 KV × 256 → 64 KB/token） |
| 训练侧（GPU1） | `max_tokens_per_mb=16384`，按 token 切 microbatch | 2B LoRA + 冻结 ViT + 梯度检查点，16k 序列 24 GB 可行；32k 单条需 `mb` 内 seq 拆分或 CP，S1 实测后决定是否把 dsh 上限降到 24k |
| macOS | **8192** | 纯 torch GDN 回退速度限制；只跑 L0 与少量 L2 |

**S1 实测项**：dsh prompt token 数、2B 在 16k/32k 单条 fwd/bwd 峰值显存、教师 Int4 打分 32 条 16k 的耗时。
