# nano-areal v0.2 更新计划（定稿：macOS + Qwen3-VL-4B + dsh）

> **取代说明：** 本文取代上一版草稿（Qwen3.5-2B 学生 + Qwen3.8-27B 蒸馏教师、2×4090 async 主路径）。该草稿作废，不再作为 v0.2 的实施依据。27B-on-4090 蒸馏优先已从本计划删除。
>
> 基线：nano-areal v0.1（Qwen3-0.6B + BFCL-V4 + GRPO，README 约 1500 行）
> 上游：areal-project/AReaL main @ 2026-09-16（v2.1.0 之后）
> 智能体：deepseek-ai/deepseek-harness（dsh，黑盒子进程，sdk-minimal）
> 默认硬件：Mac mini M4、32GB 统一内存（Mac.lan）。macOS 为主路径，`--sync` 为调试/默认运行模式
> 可选硬件：CUDA（例如 2×RTX 4090）经 `--backend cuda` 切换，不是默认路径

---

## 0. 一句话目标

**在 Mac 上，用当前能跑起来的热门开源 VLM（Qwen3-VL-4B，vllm-metal）做智能体强化学习：dsh 作为不可修改的外部智能体，nano-areal 的 DeepSeek/OpenAI 兼容代理捕获其多轮工具调用轨迹，默认同步 GRPO；算法与硬件后端都可以切换。** 对应 AReaL 2.0 的 `agent_service`（#1383）这一条 nano 主线，保持 nano 体量。蒸馏与更大教师留到可选 CUDA / 后续阶段。

## 1. 模型

### 1.1 默认学生：Qwen3-VL-4B（已核对）

推理与训练分开挂权重。32GB 统一内存上，4bit 推理和 bf16 LoRA 训练是两条驻留，不要把 4bit MLX 权重直接当训练基座。

| 角色 | Checkpoint | 用途 |
|------|------------|------|
| 推理（默认） | `mlx-community/Qwen3-VL-4B-Instruct-4bit` | vllm-metal。由 `Qwen/Qwen3-VL-4B-Instruct` 用 mlx-vlm 0.3.4 转出，约 4B |
| 训练（默认） | `Qwen/Qwen3-VL-4B-Instruct` + LoRA | MPS 或 MLX。ViT 冻结，只训语言模型的 LoRA |

`Qwen/Qwen3-VL-4B-Instruct` 的 `config.json`（`Qwen3VLForConditionalGeneration`）：

| 项 | 值 |
|----|----|
| 文本塔 | dense Qwen3：36 层，hidden 2560，FFN 9728，32 Q / 8 KV，head_dim 128，无 attention bias |
| 词表 | 151,936，embedding 与 lm_head 绑定 |
| 上下文 | 262,144（原生）。Mac 上实际 `max_model_len` 远小于此，见第 6 节 |
| 位置编码 | 交错 M-RoPE，`mrope_section = [24, 20, 20]`（合计 64，即 head_dim 的旋转半维），`rope_theta = 5e6` |
| 视觉塔 | ViT depth 24，hidden 1024，16 heads，patch 16，spatial merge 2，temporal patch 2；DeepStack 层 5 / 11 / 17，输出维 2560 |
| 特殊 token | image 151655，video 151656，vision start/end 151652 / 151653 |

**为什么默认是 4B，而不是 8B / 27B：** M4 32GB 在 `--sync` 下推理进程和训练进程共享同一块统一内存。4bit 推理权重大约数 GB，bf16 训练基座大约 8GB 量级，再加上 LoRA 状态、KV 和激活，4B 是还能同时放下的尺寸。8B 与 27B 的 bf16 基座会把这台机器挤出可训练区间。

文本侧 bf16 KV ≈ `36 × 8 × 128 × 2 × 2 = 144 KiB/token`（视觉 token 经 merger 后同样占 KV）。瓶颈是权重 + 激活 + KV 一起抢 32GB，不是某一项单独爆。

### 1.2 Stretch / 备选（不是默认）

| 模型 | 定位 |
|------|------|
| `Qwen/Qwen3-VL-8B-Instruct` | 同一 `qwen3_vl` 族、同一词表 151,936。文本 hidden 4096、36 层、8 KV，lm_head 不绑定；视觉塔 depth 27，DeepStack 8/16/24。KV/token 与 4B 同量级，权重大约翻倍。只在 Mac 上有余量或切到 CUDA 后再试 |
| Qwen3.5 多模态（含上一版的 2B hybrid） | 另一套文本栈（GatedDeltaNet hybrid），不是本版 archon 的 Mac P0。vllm-metal 若能跑，只作为以后的可选学生 |

### 1.3 为什么不沿用上一版组合

| 组合 | 结论 |
|------|------|
| Qwen3.5-2B 学生 + Qwen3.8-27B 教师，2×4090 蒸馏优先 | **作废。** 主战场是 Mac.lan 的 32GB；27B 教师不能和学生一起常驻。hybrid 教师与 Qwen3-VL 不是同一文本栈、同一词表，token 级蒸馏对不上 |
| 27B QLoRA 当学生 | 放弃 nano 体量，Mac 不可行 |
| 只继续训 Qwen3-0.6B 文本 | 留作 BFCL 回归，不是 v0.2 亮点 |
| 以 GatedDeltaNet hybrid 作为 Mac 默认 archon | 纯 PyTorch GDN 在 Apple Silicon 上只适合对拍，不适合当默认训练路径 |

## 2. 两个开关

v0.2 的产品形状是「主路径固定、两边可换」，不是把 Mac 写成 CUDA 机器的调试附属。

### 2.1 硬件：`--backend metal|cuda`

| | `metal`（默认） | `cuda`（可选） |
|--|----------------|----------------|
| 机器 | Mac mini M4 32GB（Mac.lan） | 例如 2×4090；单卡 CUDA 也走 sync |
| 推理 | vllm-metal，默认 4bit MLX checkpoint | vLLM CUDA |
| 训练 | MPS 或 MLX，LoRA | CUDA，LoRA 或之后的全参 |
| 运行模式 | `--sync`。`max_head_offpolicyness = 0` | 两卡及以上可 async（v0.1 的 buffer / off-policyness）；单卡 sync |
| 权重同步 | 现有 `copy` 回退，只推 LoRA | 两卡 async 用 awex；单卡 copy |

默认命令（路径仍是本仓库检出，不搬目录）：

```bash
# Mac.lan：默认
uv run python train.py --backend metal --sync \
  --infer-model mlx-community/Qwen3-VL-4B-Instruct-4bit \
  --train-model Qwen/Qwen3-VL-4B-Instruct \
  --loss grpo

# 以后切 CUDA，同一套 agent / proxy / 奖励
uv run python train.py --backend cuda --loss grpo
```

环境仍按 README 的 macOS 说明：Python 3.12，`uv sync --extra metal`。本文不要求改 `~/workspace` 或任何本地检出位置。

### 2.2 算法：`--loss grpo|cispo|gspo|drgrpo`

P0 只实现 **GRPO**。P1 在同一条轨迹上切换 CISPO、GSPO、Dr.GRPO，不换数据管线。macOS sync 与 CUDA async 共用 `AsyncTrajectoryBuffer`：sync 把 off-policyness 上限设为 0，过期轨迹的丢弃逻辑还在。

## 3. nano-archon：Qwen3-VL（沿用 dense 文本塔）

v0.1 的 `nano_areal/archon/model.py` 已经是 dense Qwen3（RoPE、GQA、QK-norm、SwiGLU），`from_hf_config` 会读 `text_config`。v0.2 把这条塔扩成 Qwen3-VL，而不是重写成 GatedDeltaNet。

```
nano_areal/archon/
├── model.py            现有 dense 文本塔；VLM 路径改走 M-RoPE
├── mrope.py            [新] 交错 M-RoPE，section (24, 20, 20)，rope_theta 5e6
├── vision.py           [新] ViT + patch merger + DeepStack（4B：层 5/11/17）；默认冻结
├── state_dict.py       扩到 Qwen3VLForConditionalGeneration
├── lora.py             [新] q/k/v/o 与 gate/up/down；ViT 不挂 LoRA
└── losses.py           [新] GRPO 默认；CISPO / GSPO / Dr.GRPO 为 P1 开关
```

GatedDeltaNet（`gdn.py`、fla kernel、纯 torch chunk 回退）**不是 Mac P0**。若以后要把 Qwen3.5 hybrid 收成可选学生，再单开一条 archon，仍走同一个 `--backend` 开关。

对拍：`scripts/test_archon_parity.py` 对 HF `Qwen3VLForConditionalGeneration`，文本 + 单图，logits 误差在 bf16 下按 atol 2e-2 验收。Mac 上先跑这条，再谈 CUDA。

## 4. 锚定智能体：dsh（主路径）

BFCL 留在第 5 节当 L0 回归。v0.2 的亮点智能体是 dsh，黑盒，不改它的源码。

### 4.1 契合点

| dsh 能力 | 对 nano-areal 的意义 |
|---------|-------------------|
| Python SDK 以子进程 + stdio JSON-RPC 拉起，`base_url` / `api_key` 可配 | `DshAgent.run()` 把 `base_url` 指到代理，`api_key` 用代理签发的 session key |
| `llm-deepseek` 可用 `protocol: chat-completions` + 自定义 `baseURL` | 代理实现 DeepSeek 风格 Chat Completions：SSE、`reasoning_content`、tool_calls；忽略 `dsh_session_log` / `dsh_plugin_packages` 等扩展字段 |
| `sdk-minimal`：一个持久 shell，系统提示最短 | 4B 在 32GB 上承受得住；模型名由 SDK 初始化请求指定为推理 checkpoint |
| `RunResult(final_response, finish_reason, events)` | 奖励在任务目录里算完后 `POST /rl/set_reward`；`finish_reason=max-tokens/error` 记 0 |
| 每个模型请求写入 session log | 用来核对代理捕获的 token 序列 |

图像入口（附件或 browser/computer-use 截图）留到 L3。L1 主训练集是纯文本 coding，先不把视觉 token 叠进 dsh 系统提示。

### 4.2 新增

```
nano_areal/agent/dsh.py          DshAgent：SDK 启动 dsh(sdk-minimal) → 任务 → 评分 → {response_id: reward}
nano_areal/engine/proxy.py       SSE、reasoning_content 透传、未知扩展字段忽略、tool_calls
nano_areal/reward/dsh_task.py    在任务自己的临时目录里跑隐藏测试
scripts/dsh_patch.yml            deepseek-official → chat-completions
```

每个任务使用独立临时目录。奖励脚本在代理侧跑，不信任 agent 输出。不改动本仓库的检出路径。

### 4.3 风险

1. S1 先在 Mac.lan 上跑 `dsh --profile sdk-minimal --json`，量 prompt token，再锁 `max_model_len`。
2. dsh 预览接口会变：pin SDK 版本，patch yml 入库。
3. 思考 token：代理按 vllm-metal 实际的 reasoning parser 拆出 `reasoning_content`（parser 名 S1 实测），训练时默认进入 loss。
4. 4bit 推理与 bf16+LoRA 训练的权重同步只推 LoRA，不在 MLX 4bit 与 bf16 之间整模来回量化。

| 层 | 数据集 | 在哪跑 | 奖励 | 角色 |
|----|--------|--------|------|------|

## 6. 上下文长度（max_model_len）

原生 262k 在 M4 32GB 上没有意义。先按统一内存排，S1 用实测改数字。

| 轨道 | 建议 `max_model_len` | 依据 |
|------|---------------------|------|
| Mac L0 单轮 | **4096** | 单图 merger 后仍可能有数百 vision token，prompt + 回答留余量；还要给定训练进程留内存 |
| Mac L1 dsh | **8192**（实测允许再试 16384） | sdk-minimal 系统提示 + 工具 schema 大约 2–4k；每轮 shell 输出截断；轮数少。`group_size` 用 v0.1 macOS 预设（4）或更小 |
| 训练 microbatch | 单条不超过上面的上限，按 token 预算切 | LoRA + 冻结 ViT + 梯度检查点。MPS 上 `torch.compile` 继续关闭（v0.1 `for_macos`） |
| CUDA 可选 | **16384–32768** | 推理与训练拆到不同卡后，不再和 Mac 抢同一块 32GB |

**S1 在 Mac.lan 上要量的数：** 4bit 模型加载后的内存、单图 chat 峰值、dsh prompt token、bf16+LoRA 与 vllm-metal 同时驻留时还剩多少。量完再决定 L1 用 8192 还是 16384。

## 7. 亮点 Feature List

### P0（macOS 主路径）

1. **`--backend metal|cuda`**：推理 vllm-metal / vLLM CUDA；训练 MPS 或 MLX / CUDA。默认 metal
2. **默认学生 Qwen3-VL-4B**：推理 4bit MLX，训练 bf16 + LoRA，ViT 冻结
3. **多模态轨迹 proxy**：不改 agent，捕获 token、logprobs、tool_calls、图像
4. **dsh 黑盒 subprocess**（sdk-minimal）作为主智能体
5. **可验证奖励**：nano-swe 隐藏测试
6. **GRPO + macOS sync**：buffer 与 off-policyness 保留，sync 时 gap = 0
7. **分组奖励归一化 + 不完整组安全训练**（dsh 超时/失败是常态）
8. **显式截断追踪**（`finish_reason=max-tokens`）
9. **LoRA 的 copy 权重同步**（Mac）；CUDA 两卡仍可走 awex

### P1

10. **算法开关**：CISPO / GSPO / Dr.GRPO，同一条轨迹
11. **Decoupled PPO 三套 logprob + `reuse_train_logp`**
12. **拒绝采样**
13. **BFCL-V4 回归**保持绿
14. **过程奖励**：`ToolCallValidScorer`、`LengthBudgetScorer`
15. **turn-level GAE**
16. **ChartMimic 一类 VLM coding**
17. **CLI 外壳**：`nano-areal inference | agent | train`（标志与 `train.py` 对齐）

### P2（可选 CUDA / 更晚）

18. **同词表 on-policy 蒸馏**：教师用更大的 Qwen3-VL（8B 或以上），在 CUDA 上分时或远程打分。不在 Mac 32GB 上驻留 27B，也不再把 Qwen3.8-27B 列为 P0 教师
19. **Stretch 学生探针**：Qwen3-VL-8B；Qwen3.5 多模态仅当要单开 GDN archon 时
20. awex delta 传输；多教师；Arena 多流 rollout

## 8. 分阶段实施

Mac smoke 在前。CUDA 与蒸馏不挡默认路径。验收机是 Mac.lan，不在本文里改检出位置。

| 阶段 | 内容 | 验收 |
|------|------|------|
| **S1 Mac 探针** | `--backend metal` 用 vllm-metal 拉起 4bit Qwen3-VL-4B；单图 chat；pin dsh；量内存与 prompt token；确认 logprobs 与图像 token 数 | Mac.lan 上一条带图补全成功；写下 L1 的 `max_model_len` 和训练进程能否同驻 |
| **S2 archon Qwen3-VL** | M-RoPE、ViT/DeepStack、state_dict、LoRA；文本塔复用现有 dense Qwen3 | `test_archon_parity.py` 文本 + 单图通过；MPS 上短序列若干 step 不把 32GB 打满 |
| **S3 多模态 proxy + L0** | processor、视觉字段、CLEVR loader、BFCL 回归 | Mac 上 L0 VLM 的 loss 能下降；BFCL 流程不退化 |
| **S4 dsh + nano-swe** | SSE 代理、`DshAgent`、任务临时目录、pytest 奖励、超时/失败分类 | Mac sync 下 pass 率可统计；dsh session log 与代理 token 一致 |
| **S5 算法开关** | GRPO 为默认；CISPO / GSPO / Dr.GRPO；不完整组与截断；sync gap=0 与 async 过滤共用 buffer | 四种 loss 有单测；金属路径默认仍是 GRPO |
| **S6 可选 CUDA** | `--backend cuda`：vLLM + CUDA 训练；有第二张卡时 async + awex。同一 dsh / nano-swe | 切后端后任务与奖励不变；Mac 仍是文档和默认命令里的主路径 |
| **S7 蒸馏、stretch、L3** | 同词表更大 Qwen3-VL 教师（仅 CUDA）；8B / Qwen3.5 只做探针；ChartMimic；CLI 与 README 在行为落地时再改 | 不阻塞前面的 Mac 主路径。27B-on-4090 蒸馏不回到 P0 |

S1 必须在 Mac 上跑。vllm-metal 对 Qwen3-VL 的 logprobs、M-RoPE 图像输入，以 S1 实测为准；对不上就改代理，不改默认模型家族。
